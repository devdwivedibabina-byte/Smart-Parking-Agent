### The Urban Parking Problem
In congested urban commercial centers, university campuses, and transportation hubs, drivers expend significant time searching for vacant parking bays. Empirical studies indicate that **up to 30% of downtown traffic congestion** is generated by drivers "cruising" for parking. This inefficiency results in:
1. Significant fuel consumption and rapid electric vehicle battery depletion.
2. Elevated greenhouse gas emissions ($CO_2$, particulate emissions).
3. Driver frustration, cognitive fatigue, and lost productive time.
4. Severe localized traffic bottlenecks at entrance corridors.

### The Proposed Intelligent Solution
The **Smart Parking Management Agent** acts as an autonomous rational coordinator. It ingests real-time IoT presence telemetry, perceives driver entry coordinates $(x_d, y_d)$, vehicle constraints (Regular, Electric Vehicle with charging, Accessible/Disabled), and maximum walking endurance boundaries. Utilizing a strict constraint-satisfaction and Euclidean utility minimization pipeline, the agent calculates and recommends the globally optimal parking bay in deterministic $O(N)$ time with explainable AI reasoning.

## 2. Formal PEAS Representation

The Russell & Norvig framework formalizes intelligent agents through **PEAS** (Performance measure, Environment, Actuators, Sensors):

| PEAS Component | System Formalization | Detailed Specification |
| :--- | :--- | :--- |
| **P – Performance Measure** | Proximity Utility & Safety | • Minimize pedestrian walking distance: $\min \sqrt{(x_s - x_d)^2 + (y_s - y_d)^2}$<br>• Minimize search time (algorithmic allocation $< 5\text{ms}$)<br>• Maximize allocation success rate ($100\%$ conflict-free)<br>• Zero allocation of Occupied or Reserved bays<br>• $100\%$ compliance with EV and Accessible parking mandates |
| **E – Environment** | 2D Metric Spatial Grid | • 36 discrete parking bays organized into Zone A (North), Zone B (Central), and Zone C (South)<br>• Metric 2D coordinates $(X, Y)$ in meters with designated driving lanes and crosswalks<br>• Dynamic, non-deterministic vehicle arrivals and departures over time<br>• Heterogeneous bay categories: Regular bays, Level 2/DC Fast EV bays, Accessible ramp bays |
| **A – Actuators** | Telemetry Guidance System | • Visual navigation spotlight on dashboard interactive layout<br>• Animated radar indicator highlighting the winning parking bay<br>• Automated slot state reservation and locking mechanism<br>• Real-time walking distance and estimated walk time display<br>• Explainable AI reasoning narrative and runner-up alternative delivery |
| **S – Sensors** | IoT & Driver Telemetry | • Simulated ultrasonic/magnetic ground sensors monitoring bay occupancy status (`Available`, `Occupied`, `Reserved`)<br>• Driver location sensor (Entrance Gate coordinates: Gate A, Gate B, Gate C, or custom coordinates)<br>• Vehicle type requirement sensor (Regular, EV, Disabled)<br>• Maximum acceptable walking distance boundary slider |

## 3. Environment Classification (Russell & Norvig AI Taxonomy)

| Environment Dimension | Classification | Justification |
| :--- | :--- | :--- |
| **Observability** | **Fully Observable** | Simulated IoT ground telemetry exposes the exact operational state (`Available`, `Occupied`, `Reserved`) of all 36 parking bays simultaneously. |
| **Determinism** | **Deterministic (Allocation) / Stochastic (Traffic)** | For any fixed environment snapshot, the agent's decision is $100\%$ deterministic. The arrival and departure of external vehicles follow a stochastic process. |
| **Episodic vs. Sequential** | **Episodic** | Each parking recommendation query represents an independent episode: the agent perceives current coordinates and telemetry, evaluates candidates, and selects the optimal action. |
| **Static vs. Dynamic** | **Dynamic** | The environment state can change (e.g., another car parks in a spot) while the agent deliberates or while the driver is in transit. |
| **Discrete vs. Continuous** | **Discrete Bays / Continuous Space** | Parking bays, occupancy states, and vehicle classes are discrete entities; physical distances and coordinates exist within a continuous 2D spatial metric. |
| **Single vs. Multi-Agent** | **Single Coordinator** | The agent functions as a centralized smart-city coordinator managing allocation across all drivers. |

## 4. Intelligent Agent Architecture & Decision Logic

```
   [ Driver Entrance / GPS ]     [ IoT Bay Telemetry (36 Bays) ]
               │                                │
               └───────────────┬────────────────┘
                               ▼
               ┌────────────────────────────────┐
               │    STEP 1: SENSE & PERCEIVE    │
               │   Ingest (xd, yd), Type, Dmax  │
               └───────────────┬────────────────┘
                               ▼
               ┌────────────────────────────────┐
               │  STEP 2: OCCUPANCY FILTERING   │
               │  Eliminate Occupied & Reserved │
               └───────────────┬────────────────┘
                               ▼
               ┌────────────────────────────────┐
               │    STEP 3: TYPE COMPLIANCE     │
               │ Match Regular / EV / Disabled  │
               └───────────────┬────────────────┘
                               ▼
               ┌────────────────────────────────┐
               │  STEP 4: EUCLIDEAN METRIC CALC │
               │  d = sqrt((xs-xd)^2+(ys-yd)^2) │
               └───────────────┬────────────────┘
                               ▼
               ┌────────────────────────────────┐
               │  STEP 5: DISTANCE PRUNING      │
               │   Eliminate bays with d > Dmax │
               └───────────────┬────────────────┘
                               ▼
               ┌────────────────────────────────┐
               │  STEP 6: UTILITY OPTIMIZATION  │
               │  U(s) = -d; Tie-breaker: ID    │
               └───────────────┬────────────────┘
                               ▼
               ┌────────────────────────────────┐
               │   STEP 7: ACTUATE & GUIDANCE   │
               │ Highlight Winner, Lock Bay     │
               └────────────────────────────────┘
```

### Mathematical Utility Function
The agent evaluates candidate parking spaces $s \in S_{\text{feasible}}$ using a negative distance cost utility formulation:
$$U(s) = - \text{Euclidean\_Distance}(\text{driver}, s) = - \sqrt{(x_s - x_d)^2 + (y_s - y_d)^2}$$

The optimal rational action $s^*$ maximizes utility (minimizing walking distance):
$$s^* = \arg\max_{s \in S_{\text{feasible}}} U(s) = \arg\min_{s \in S_{\text{feasible}}} \sqrt{(x_s - x_d)^2 + (y_s - y_d)^2}$$

### Deterministic Tie-Breaking Rule
If two or more available bays yield identical Euclidean distances within a floating-point tolerance $\epsilon = 10^{-4}\text{ meters}$, the agent breaks ties by choosing the bay with the lexicographically smaller alphanumeric identifier (e.g., `P03` takes priority over `P07`).

## 5. Dataset Specification

The simulated environment contains **36 parking spaces** arranged realistically across 3 distinct architectural zones:

* **Zone A (Slots P01 to P12):** Upper row along the North wing, adjacent to Entrance Gate A ($x=0, y=10$) and pedestrian exit. Includes Level 2 EV charging stations (P01, P02) and Accessible ramp bays (P11, P12).
* **Zone B (Slots P13 to P24):** Central double-sided bays separated by an access median, adjacent to Gate B ($x=15, y=0$). Features Tesla/CCS EV chargers (P13) and wheelchair accessible bays (P23, P24).
* **Zone C (Slots P25 to P36):** Lower row along the South wing, adjacent to Gate C ($x=30, y=10$) and public transit shuttle links. Features 50kW DC Fast EV chargers (P25, P26) and accessible bays (P35, P36).

Each record contains:
```json
{
  "id": "P01",
  "slot_number": 1,
  "zone": "Zone A",
  "x": 3.0,
  "y": 4.0,
  "status": "Available",
  "parking_type": "EV",
  "hourly_rate": 3.50,
  "features": "Level 2 Fast Charger"
}
```

## 9. University Viva Examination Questions & Model Answers

### Q1: What specific type of agent is implemented in this system?
> **Answer:** It is a **Utility-Based, Goal-Driven Rational Agent**. It maintains explicit goals (satisfying availability, matching vehicle type, and adhering to maximum walking distance constraints) and evaluates candidate states using a continuous mathematical utility function $U(s) = -\text{Distance}(s)$. The action that maximizes expected utility (minimizes walking distance) is chosen.

### Q2: How does the agent satisfy the definition of rationality?
> **Answer:** As defined by Russell & Norvig, an agent is rational if, for each possible percept sequence, it selects an action expected to maximize its performance measure given current percepts and built-in knowledge. Our agent mathematically guarantees the lowest Euclidean walking distance among all eligible bays while eliminating occupied and inappropriate bays.

### Q3: Why is Euclidean distance used instead of Manhattan distance?
> **Answer:** While Manhattan distance is suited for orthogonal city street grids, pedestrian parking structures feature wide open aisles, diagonal walking corridors, and pedestrian crosswalks. Direct Euclidean metric $\sqrt{\Delta x^2 + \Delta y^2}$ models true pedestrian traversal distance accurately.

### Q4: How does the agent prevent race conditions if multiple drivers arrive?
> **Answer:** When an optimal bay is recommended, the system supports a reservation lock (`status: Reserved`), transitioning the bay out of the available pool to prevent double-allocation before physical occupancy.
